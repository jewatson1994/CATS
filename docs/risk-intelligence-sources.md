# Risk intelligence source authority and operations

Research checked 2026-10-19 against publisher documentation and public endpoints. The publisher matrix is a research inventory, not a claim that every listed feed is included. See [embedded release inventory](embedded-intelligence.md) for the actual packaged sources and measured counts. Catalog entries default disabled. A generic OpenVEX/CSAF document importer does not implement provider discovery, directory traversal, index pagination, signatures, OSV conversion, OVAL evaluation, or the publisher's version-comparison semantics.

## Authority rules

Vendor/distribution applicability statements apply only to the publisher's own products and precisely matched package, version, release and architecture. They do not establish that another distribution, rebuilt package or downstream image is unaffected. A trustworthy source name or HTTPS download does not by itself authenticate a document author. Record transport provenance, publisher identity, retrieval time, source revision, content hash, license, original product identifiers and any verified signature separately.

OSV/GHSA are package advisory intelligence; NVD is general vulnerability enrichment; KEV is observed-exploitation prioritization; EPSS is a prediction; Vulnrichment is enrichment. None is a substitute for an exact authoritative not-affected assertion. Missing records, absent KEV membership, low EPSS, unsupported formats, ambiguous product matches and stale assertions must never become not-affected. Conflicting valid evidence remains visible. Preserve original scanner findings and explain any separately derived effective disposition.

## Recommended integration sequence

1. Offline/imported OpenVEX and CSAF documents with bounded size/depth, strict schema/semantic checks, immutable originals and explicit issuer scope.
2. Inventory-scoped Red Hat and SUSE documents where exact product identities are available. Provider catalogs remain disabled until discovery, allowed-host policy, signatures when supplied, checkpoints and error visibility are implemented.
3. KEV and daily EPSS as independent priority inputs; retain data dates and missing-data state. OSV/GHSA only for relevant ecosystems.
4. Distribution-specific OVAL/SecDB/tracker and Microsoft CVRF adapters after version/suite semantics are tested. Cisco after credentials/terms configuration. Chainguard after current feed terms are reviewed.

A suggested retention policy is current normalized data, immutable documents actually used in decisions, and 30 days of sync metadata. Keep superseded decision evidence for the organization's audit period. These are defaults, not regulatory requirements. Track actual compressed/uncompressed bytes, record counts and database growth before widening scope. Network failures must leave last-good data marked with its original timestamp; never report a failed refresh as current.

## Offline fixture provenance

`portal/tests/fixtures/vex/provenance.json` records original URL, retrieval timestamp, byte count, SHA-256 and license. Files are saved without JSON rewriting.

- `redhat-cve-2024-3094.json`: real Red Hat CSAF 2.0 VEX for the xz backdoor CVE, downloaded from the official per-CVE feed; 27,408 bytes at retrieval. Contains product-specific `known_not_affected` assertions; tests should verify those assertions do not apply to unrelated products. Copyright Red Hat, CC-BY-4.0; attribution and source retained here and in the manifest.
- `openvex-official-fixed.json`: official OpenVEX project's pinned vexctl example, Apache-2.0, `fixed` status with a generic package identifier. It uses a fictional example CVE and is not a vendor attestation.
- `csaf-official-example.json`: the paired official upstream CSAF example, Apache-2.0. Also example data, not a production vendor assertion. The upstream Apache license is included as `LICENSE-openvex.txt`.

Offline tests must read these local files without fetching URLs. Real documents remain evidence of the publisher's statement at retrieval, not a perpetual guarantee or signature verification claim.
