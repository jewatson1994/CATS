## Scope and architecture

System A remains authoritative for discovery, scanning, remediation, risk and Cyber approval. Publication freezes a complete service snapshot and BOE, signs the release, and binds immutable artifact digests, approval time and expiry. Harbor copies the entire release graph into System B’s local registry. Registry transport credentials and CA trust are separate from the independently delivered publisher fingerprint.

System B runs only PostgreSQL, portal/API and OCI proxy from `templates/compose.replica.external-ingress.yaml`; its local registry and HTTPS ingress are supporting infrastructure. Background synchronization verifies signed manifests, evidence and every referenced image/index/chart/config/layer/signature before a transaction replaces the active local projection. Earlier releases and their original evidence remain retained. Assessment workers and risk-intelligence ingestion are absent.

The OCI proxy authenticates a scoped machine principal and checks current local release authorization. Superseded, expired and revoked digests are denied by default. Local Cyber overrides are separately authorized, audited exceptions for the intended immutable release/artifact inventory; they cannot override cryptographic integrity, publisher trust or authentication. Cached bytes do not confer authorization.

Three evidence classes are kept separate: (1) actual previously scanned/hardened nginx, independently downloaded from System A and freshly imported into System B; (2) synthetic rich source fixtures using production capture/import and native HTTP views; (3) synthetic inventory/graph content using actual signing, Docker execution, Harbor replication and local HTTP/OCI enforcement. No new nginx scan was performed in this task.
