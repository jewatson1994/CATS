# Embedded vulnerability and VEX intelligence sources

This reference preserves the source inventory and measured snapshot recorded in the previous README. Counts describe that release snapshot, not every later image; inspect the selected image's signed manifest for its exact contents. See the [documentation index](README.md) for deployment and operational guides.


CATS includes a signed, compressed intelligence snapshot in the normal portal and unified application images. Both Dockerfiles verify its Ed25519 signature and payload checksums. At startup, CATS verifies the local package and imports it into PostgreSQL before becoming ready. No external feed, separate intelligence service, or manual first import is required offline. Source links below are provenance references for analysts and connected release builders.

The signature authenticates the CATS release; it does not attest that every upstream document has an independently verified publisher signature. Acquisition uses allowlisted HTTPS sources and pinned input hashes. Original VEX objects and provenance are retained. Only trusted, fresh VEX with exact package, version, distribution and applicable qualifiers can establish applicability. Red Hat and SUSE also require the complete publisher-scoped CSAF containing-product context. A scanner distribution name/version alone cannot prove an enterprise product, module or edition. Versionless, missing, stale, ambiguous and conflicting evidence cannot establish an exact disposition. Supplemental advisories, exploitation evidence and scores never establish Not Affected or rewrite scanner findings, compliance decisions or Cyber approval policy.

Authoritative package identity resolution also uses the installed package database already captured by Syft/Grype. Verified Debian/Ubuntu binary-to-source records preserve namespace, version/epoch, architecture and installed release; derived identities remain separate from the original scanner identity. Debian Source omission semantics follow [Debian policy](https://www.debian.org/doc/debian-policy/ch-controlfields.html#source) and the [captured Syft parser](https://github.com/anchore/syft/blob/v1.31.0/syft/pkg/cataloger/debian/parse_dpkg_db.go). RPM source relationships remain diagnostic until source epoch and publisher product/module/edition context are proved. No additional vendor index, mapping service or redistributed feed is introduced. See the [identity resolution implementation and real-image audit](authoritative-package-identity-resolution.md) for provenance, source licensing, limits and measured coverage.

Refreshes are explicit connected release builds. An unchanged package is verified and skipped; newer sequences import atomically, and older packages cannot downgrade the installed corpus. Failed imports retain the previous committed evidence and report failure in Configuration intelligence settings. Initial import delays readiness; plan deployment timeouts and storage using the [measured release results](embedded-intelligence.md#measured-release-results). Freshness uses original publication and acquisition dates, never deployment time. Existing administrator trust settings and historical assessments are preserved.

Native VEX effective disposition is available under **Administration → General Policy** and is **disabled by default**, including upgrades. When enabled, only current verified Not Affected observations leave actionable calculations; original scanner evidence and human decisions remain intact. Services/Raw Findings expose exclusion evidence, and **Administration → Risk Policy** contains group-scoped profiles and assessment review. The existing `risk-worker` must run, including offline deployments. See [native VEX lifecycle, deployment and evidence limits](native-vex-disposition.md); controlled positive tests do not close the real-image applicability gap.

Source terms apply to the corresponding data and adaptations; there is no common license over all 13 sources, and inclusion does not imply publisher endorsement. The [signed manifest](../portal/app/embedded_intelligence_data/manifest.json) records exact counts, hashes, acquisition dates and exclusions. Source freshness defaults are seven days for EPSS and 30 days for the other sources; individual VEX evidence must also pass publication-age checks. Normalized statement totals include overlapping evidence and rows lacking the version/context needed for a current match. The [read-only evidence API](supplemental-evidence-api.md) exposes supplemental retained history with provenance and explicitly unevaluated current membership/applicability.

All selected release downloads use public HTTPS without API credentials. The [access-path and request-limit review](supplemental-source-research.md#access-paths-and-request-limit-evidence) lists the bulk or indexed route for every included source and distinguishes observed access from unestablished numeric quotas. SUSE uses bounded concurrent individual downloads; other inputs use static archives or snapshots. The application performs no feed polling.

### Deferred sources and inclusion criteria

Public access and software-code licensing alone do not establish permission to redistribute security data. Inclusion requires reviewed data terms, bounded acquisition and parsing, and preserved identities; product applicability additionally requires a reviewed exact identity mapping.

- **Microsoft MSRC:** its [CVRF API](https://github.com/microsoft/MSRC-Microsoft-Security-Updates-API) and [Azure Linux CSAF VEX](https://www.microsoft.com/en-us/msrc/blog/2025/10/toward-greater-transparency-machine-readable-vulnerability-exploitability-xchange-for-azure-linux) are available. A feed-specific redistribution grant has not been established under the reviewed [terms](https://www.microsoft.com/en-us/legal/terms-of-use), and an exact product-ID mapping adapter is not implemented. This is not a claim that Microsoft has no VEX feed.
- **Chainguard/Wolfi:** current OSV/SecDB feeds have [data-specific terms](https://github.com/chainguard-dev/vulnerability-scanner-support/blob/main/docs/foundational_concepts.md), including CC-BY-NC-ND-4.0 or the [conditional commercial-scanner license](https://www.chainguard.dev/legal/chainguard-license-for-commercial-scanners). Eligibility and downstream redistribution rights for this bundle are not established; exact component/architecture mapping also needs review. Chainguard also publishes a separate current [Libraries OpenVEX feed](https://libraries.cgr.dev/openvex/v1/); this review has not established a redistribution grant for that VEX data, and does not assume the OSV terms cover it. Exact `+cgr` identities and origin must be preserved. An archived Wolfi feed cannot represent current coverage.
- **Debian Security Tracker:** its [JSON export](https://security-tracker.debian.org/tracker/data/json) is technically feasible, but this review found no explicit tracker-data redistribution grant; the distinction is also raised in [Debian's own mailing list](https://lists.debian.org/debian-security-tracker/2026/09/msg00023.html). Source-package/release status would require verified source-to-binary mapping before any installed-package applicability claim. No Debian data is substituted through OSV.
