## Existing bounded or bulk paths to preserve

- `main.py:2190` selects `service_overview_rows_aggregated`, rather than the legacy detailed helper. Finding/policy counts, active exception checks, overdue policy and oldest dates are database aggregates.
- `findings_sql.py:28` performs SQL filtering/counting/order/offset/limit; it hydrates selected findings and current exceptions only. Observation search is bounded to 20 candidates in the relevant search expression. Preserve current latest-observation and evidence semantics.
- `/api/dashboard/cybersecurity/services/{service_key}/history` (`main.py:6379`) uses `security_dashboard.bounded_service_history`: at most 128 metadata candidates, eight trend snapshots and two version snapshots; at most ten full payloads are hydrated. `service_history` is the legacy relationship-driven helper, not proof of unbounded behavior on this route.
- `/remediations` (`main.py:7995`) already scopes remediation queries, SQL-filters, counts and pages POAM/exception records with selected related objects. It loads all authorized services for selectors and performs service-name/key matching in Python before building filter IDs; this is a smaller residual improvement than whole evidence graphs.
- `/api/admin/validators` (`validator_management.py:165`) iterates all nonremoved validators but calls `public_validator(v)` without a database argument, so it does **not** query attempts per row. Validator detail calls `public_validator(v, db)` and bounds attempts to 30. Avoid reporting a nonexistent validator listing N+1. Provisioning readiness and payload status involve synchronous payload inspection; measure before caching or moving work.

## Schema and authorization conventions

SQLAlchemy models live in `portal/app/models.py`; tables use snake_case names, integer IDs for services/findings/executions, JSON evidence fields, timezone-aware timestamp declarations, and relationships that default to lazy loading. `Execution.raw_payload` contains retained scan evidence. `FindingObservation.evidence`, artifact revision files and audit event detail are also JSON. `Finding` uniqueness is `(service_id, cve)`; policy findings use `(service_id, identity_key)`.

`accessible_service_ids(permission)` returns `None` for unrestricted scope and a set for restricted scope; callers must preserve empty-scope denial where currently enforced. Detail dependencies use scoped permissions. Dashboard and export permissions differ (`service.view` versus `service.export`); summary reuse must not broaden exported scope. Global and group-scoped configuration must keep established precedence.

Existing startup index declarations are in `main.py:289-299`: service/active finding and policy indexes, service/scanned execution index, service/status/due POAM index, observation finding/ID and finding/execution/ID indexes, finding/policy ordering indexes, artifact-validation foreign-key index, and current-exception composite indexes. Models additionally declare indexed foreign keys and timestamps. Verify actual schema/index presence and query plans before adding duplicates. PostgreSQL and SQLite paths both exist; use portable JSON expressions or explicit tested dialect branches.

## Evidence and verification boundaries

This inventory does not establish production query counts, p95 latency, memory, throughput, or request sizes. Existing historical measurements in `portal/docs/findings-performance.md` describe an earlier findings change, not this refactor's baseline. `tools/benchmark_services_overview.py` and `tools/benchmark_service_findings.py` provide starting harnesses with query timing and plan capture; record fixture size, dialect, request parameters and response equivalence for new measurements. Confirm suspected lazy-load N+1 cases with query listeners rather than claiming them from relationship declarations alone.

Frontend projection modules (`frontend.py`, `frontend_portfolio.py`, `frontend_service_operations.py`, `frontend_service_secondary.py`, `frontend_remediations.py`) largely adapt route context into JSON. Optimize the context loaders first while keeping both HTML and page-JSON contracts consistent.
